# Модуль 3 — задание 6

Групповой чат на C с использованием широковещательной UDP-рассылки.
Все запущенные экземпляры программы равноправны: отдельного сервера нет.

## Что реализовано

- UDP-сокет `AF_INET + SOCK_DGRAM`;
- широковещательная отправка через `sendto()`;
- приём сообщений через `recvfrom()`;
- `SO_BROADCAST` для разрешения broadcast-отправки;
- `SO_REUSEADDR`, чтобы несколько экземпляров можно было запускать на одном хосте;
- сообщение о подключении нового участника;
- обычные сообщения чата;
- сообщение об отключении;
- корректное завершение по `/quit`, `Ctrl+C` и `SIGTERM`;
- одновременное ожидание клавиатуры и сети через `select()`;
- unit-тесты и интеграционный тест с тремя клиентами.

## Как работает программа

Каждый экземпляр выполняет одновременно две задачи:

1. ждёт ввод пользователя с клавиатуры;
2. ждёт UDP-дейтаграммы от других участников.

Для этого используется `select()`.

При запуске клиент отправляет широковещательный пакет `JOIN`.
Остальные участники выводят сообщение о новом клиенте.

Обычный текст отправляется пакетом `MESSAGE`.
Все другие экземпляры программы, работающие на том же UDP-порту и в той же
широковещательной сети, получают его.

При `/quit`, `Ctrl+C` или `SIGTERM` перед закрытием сокета отправляется пакет
`LEAVE`.

У каждого процесса есть собственный `sender_id`. Полученное сообщение с таким
же `sender_id` не выводится, поэтому клиент не показывает собственный broadcast
повторно.

## Протокол сообщения

Пакет содержит:

```text
magic
version
type
sender_id
name
text
```

Типы пакетов:

```text
JOIN     — участник подключился
MESSAGE  — обычное сообщение
LEAVE    — участник отключился
```

Числовые поля передаются в сетевом порядке байтов через `htonl()` / `ntohl()`.

## Быстрая демонстрация на одном компьютере

Откройте три терминала в каталоге `06`.

Терминал 1:

```bash
./udp_chat -n Alice
```

Терминал 2:

```bash
./udp_chat -n Bob
```

Терминал 3:

```bash
./udp_chat -n Carol
```

После запуска Bob в терминале Alice появится сообщение о подключении Bob.
После запуска Carol остальные работающие клиенты увидят её подключение.

Введите текст в любом терминале и нажмите Enter — сообщение появится у других
участников.

Завершение:

```text
/quit
```

или `Ctrl+C`.

## Запуск между разными компьютерами / виртуальными машинами

Все машины должны быть в одной сети и использовать одинаковые UDP-порт и
broadcast-адрес.

Посмотреть IPv4-адрес и broadcast интерфейса в Linux:

```bash
ip -4 addr
```

Например, если интерфейс показывает:

```text
inet 192.168.1.25/24 brd 192.168.1.255
```

то программу на всех машинах можно запускать так:

```bash
./udp_chat -n Alice -a 192.168.1.255 -p 51006
./udp_chat -n Bob   -a 192.168.1.255 -p 51006
```

По умолчанию используется ограниченный broadcast:

```text
255.255.255.255:51006
```

Если сеть или виртуальная машина не пропускает limited broadcast, лучше явно
указать broadcast конкретной подсети через `-a`.

## Тесты

Запуск всех тестов:

```bash
make test
```

Unit-тесты проверяют:

1. формирование и проверку пакета;
2. тип и идентификатор отправителя;
3. разбор UDP-порта;
4. формирование IPv4 broadcast-адреса;
5. отклонение некорректных данных.

Интеграционный тест автоматически запускает три равноправных клиента:
`Alice`, `Bob`, `Carol`.

Проверяется:

1. успешный запуск и завершение трёх клиентов;
2. уведомление о подключении;
3. доставка сообщения Alice двум другим клиентам;
4. доставка сообщения Bob двум другим клиентам;
5. отсутствие повторного вывода собственного сообщения;
6. уведомление об отключении Bob.

## Как убедиться в правильности программы

### 1. Несколько равноправных клиентов

Запустить три терминала:

```bash
./udp_chat -n Alice
./udp_chat -n Bob
./udp_chat -n Carol
```

Показать, что отдельного сервера нет.

### 2. Broadcast-сообщения

Отправить сообщения из разных терминалов и показать их появление у остальных
участников.

### 3. Отключение

В одном клиенте выполнить:

```text
/quit
```

Остальные должны вывести сообщение об отключении.

### 4. UDP-сокет в системе

Во время работы:

```bash
ss -lunp | grep 51006
```

### 5. Сетевой трафик

При наличии `tcpdump`:

```bash
sudo tcpdump -ni any udp port 51006
```

Или использовать Wireshark с фильтром:

```text
udp.port == 51006
```

Будет видно UDP-дейтаграммы, отправленные на широковещательный адрес.
