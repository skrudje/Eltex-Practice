# Модуль 3 — задание 5

Модель «Производитель–Потребители» с использованием POSIX IPC.

Задание повторяет логику задания 4, но вместо System V используются:

- разделяемая память POSIX: `shm_open`, `ftruncate`, `mmap`, `munmap`, `shm_unlink`;
- именованный семафор POSIX: `sem_open`, `sem_wait`, `sem_post`, `sem_close`, `sem_unlink`;
- несколько независимых процессов-потребителей;
- наборы чисел размещаются в общей памяти как цепочка блоков.

## Как устроены данные

В начале общей памяти находится служебный заголовок `SharedHeader`.
После него последовательно размещаются блоки с массивами.

Каждый блок имеет вид:

```text
next_offset
count
values...
```

`next_offset` — смещение следующего блока от начала общей памяти.
У последнего блока `next_offset == 0`.

Используется именно смещение, а не обычный указатель C, потому что разные
процессы могут отобразить один объект POSIX shared memory по разным виртуальным
адресам.

После обработки массива потребитель устанавливает `count = 0`, как требуется
в условии. Поле `next_offset` не изменяется, поэтому цепочка блоков сохраняется.

## Синхронизация

Для доступа к разделяемой памяти используется один именованный POSIX-семафор.

Перед работой с общей памятью процесс вызывает:

```c
sem_wait(...)
```

После завершения работы:

```c
sem_post(...)
```

Таким образом одновременно изменять общую память может только один процесс.
Это не позволяет двум потребителям обработать один и тот же блок.

## Сборка

```bash
make
```

Будет создан исполняемый файл:

```text
shared_list
```

## Запуск

Сначала в первом терминале запускается производитель:

```bash
./shared_list -p
```

Затем в других терминалах можно запустить несколько потребителей:

```bash
./shared_list -c
./shared_list -c
./shared_list -c
```

Производитель периодически создаёт случайные массивы и добавляет их в общую
память до тех пор, пока свободного места недостаточно для следующего блока.
После этого он отмечает завершение генерации и ждёт обработки всех наборов.

Каждый потребитель периодически ищет один необработанный блок, определяет
минимальный и максимальный элементы, выводит результат и устанавливает
`count = 0`.

Когда генерация закончена и необработанных блоков больше нет, потребители
завершаются. После завершения всех потребителей производитель удаляет POSIX
shared memory и POSIX semaphore.

## Просмотр POSIX IPC в Linux

Именованные POSIX-объекты можно увидеть в `/dev/shm`.

Во время работы программы:

```bash
ls -l /dev/shm | grep eltex_module3_task5
```

Обычно будут видны объекты примерно с такими именами:

```text
eltex_module3_task5_shm
sem.eltex_module3_task5_sem
```

## Аварийная очистка

Если программа была остановлена принудительно и объекты остались:

```bash
./shared_list --cleanup
```

или:

```bash
make clean-ipc
```

## Тесты

Запустить все тесты:

```bash
make test
```

Сначала выполняются модульные тесты функции поиска min/max и проверок структур.
Затем интеграционный тест:

1. проверяет запуск потребителя без производителя;
2. запускает одного производителя;
3. запускает три процесса-потребителя;
4. проверяет успешное завершение процессов;
5. сравнивает число созданных и обработанных блоков;
6. проверяет отсутствие повторной обработки одного блока;
7. проверяет удаление POSIX IPC-объектов из `/dev/shm`.

## Очистка файлов сборки

```bash
make clean
```

## Основное отличие от задания 4

В задании 4 использовались System V IPC:

```text
shmget / shmat / shmdt / shmctl
semget / semop / semctl
```

В задании 5 та же логика реализована средствами POSIX:

```text
shm_open / mmap / munmap / shm_unlink
sem_open / sem_wait / sem_post / sem_unlink
```
